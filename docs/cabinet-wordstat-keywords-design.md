# Подбор слов Wordstat — дизайн модуля

Статус: дизайн согласован 2026-11-23, реализация по этапам 1 → 2 → 3.
Slug модуля: `wordstat-keywords`. Версия: `config/cabinet-wordstat-keywords.php`, журнал: `docs/cabinet-wordstat-keywords-changelog.md`.

## Зачем

Собрать семантическое ядро сайта в кабинете: ввести фразы (или дать сайт), получить левую и правую колонки Wordstat, сразу разложить по группам, почистить и отдать дальше (XLSX, кластеризатор, мониторинг).

## Definition of done (этап 1)

Пользователь создаёт проект на домен, вставляет одну или несколько фраз (можно с группами), выбирает пресет, видит оценку «примерно N запросов», запускает сбор. Сбор идёт в фоне с прогрессом; закрытие вкладки сбор не прерывает. После F5 видны группы и фразы с частотностью, источником (левая/правая колонка) и выгрузка в XLSX. Действия в проекте — без перезагрузки страницы.

Не делаем в этапе 1: автоматический режим по сайту, точную частотность, подсказки, Вебмастер/GSC, маркер коммерции, лимиты тарифа.

## Источник данных

- Wordstat API xmlstock: `https://xmlstock.com/wordstat/json/`, `pagetype=words`, `regions=<id,…>`, `device=…`.
- Ответ: `totalCount`, `results` (левая колонка, до 2 000 фраз), `associations` (правая колонка). Числа приходят строками.
- Проверено с prod 2026-11-23 днём: «натяжные потолки», регион 213 — ответ за 0,6 с, 2 000 / 19 фраз. Ночного окна, как у XML-выдачи Яндекса, нет.
- Точная частотность (этап 2): отдельный запрос на фразу с операторами `"!слово !слово"`, берём `totalCount`.
- Учётные данные — `config('xmlstock.user')`, `config('xmlstock.key')`. Допустимая скорость неизвестна → настройка `wordstat_rps` в админке (по умолчанию 5 запросов/с), лимитер по образцу `PositionCollectRateLimiter`.
- В UI имя поставщика не показываем (правило `no-vendor-names-in-ui`): «Wordstat», «сбор частотности».

## Сущности (таблицы)

| Таблица | Ключевые поля |
|---|---|
| `wordstat_projects` | `user_id`, `team_id` null, `domain`, `region_ids` json (по умолчанию), `device`, `title`, timestamps, soft delete |
| `wordstat_groups` | `project_id`, `name`, `page_url` null (этап 3), `source` (`manual` / `site`), `position` |
| `wordstat_phrases` | `project_id`, `group_id`, `phrase`, `phrase_key` (нормализованный ключ для дублей), `freq` (базовая), `freq_exact` null, `source` (`left` / `right` / `suggest` / `webmaster` / `gsc` / `manual`), `seed_phrase_id` null, `depth`, `status` (`active` / `minus` / `deleted`), `is_commercial` null, `run_id`; уникальность `(project_id, phrase_key)` |
| `wordstat_runs` | `project_id`, `user_id`, `settings` json (снимок пресета), `status` (`queued` / `running` / `done` / `failed` / `cancelled`), `seeds_total`, `seeds_done`, `requests_estimated`, `requests_used`, `phrases_added`, `error` null, `started_at`, `finished_at` |
| `wordstat_run_seeds` | `run_id`, `group_id`, `phrase`, `depth`, `status`, `requests_used`, `error` null |
| `wordstat_presets` | `user_id`, `team_id` null (общий на команду), `title`, `settings` json |
| `wordstat_request_log` | `user_id`, `project_id`, `run_id`, `kind` (`words` / `exact`), `created_at` — основа счётчика по пользователю и месяцу и будущих лимитов |

Одна фраза в проекте живёт в одной группе (уникальность по `phrase_key`). Если сбор другой группы нашёл ту же фразу — не дублируем, а пишем конфликт (этап 2: «фраза в двух группах», выбор группы).

`phrase_key`: нижний регистр, `ё → е`, схлопнуть пробелы, убрать операторы Wordstat; в этапе 2 — сортировка слов и лемма для неявных дублей.

## Пресет (`settings` json)

```json
{
  "region_ids": [213],
  "device": "all",
  "columns": ["left", "right"],
  "left_limit": 200,
  "depth": 0,
  "depth_left_limit": 50,
  "depth_max_seeds": 100,
  "minus_words": ["бесплатно", "своими руками"],
  "stop_words": [],
  "exact_freq": false
}
```

- `device`: `all` / `desktop` / `phone` / `tablet`.
- `left_limit`: сколько фраз брать из левой колонки (1–2 000).
- `depth`: 0 — только затравки; 1–2 — дособирать по найденным фразам. `depth_left_limit` и `depth_max_seeds` — жёсткие ограничители расхода.
- `minus_words`: фраза с таким словом не сохраняется. `stop_words`: слово вырезается из затравки перед запросом.
- `exact_freq` (этап 2): после чистки дособрать точную частотность.
- Пресеты бывают личные (`team_id` null) и общие на команду (видят все её участники, правит автор). Встроенный пресет «По умолчанию» есть в коде.

## Ввод фраз (ручной режим)

Одно поле textarea, разбор на сервере:

- одна строка — одна фраза, всё в группу «Без группы» или выбранную;
- `Группа: фраза` — фраза в эту группу (создаётся при отсутствии);
- строка `# Группа` — все фразы ниже идут в эту группу;
- вставка из Excel: две колонки через Tab — `группа<TAB>фраза`.

Перед запуском — предпросмотр: N групп, M затравок, оценка запросов.

## Оценка и счётчик запросов

- Оценка: `seeds × (1 если columns не пусты)` + при `depth ≥ 1` — до `depth_max_seeds` на уровень (верхняя граница) + при `exact_freq` — по одной на фразу после фильтров (этап 2, оценивается после основного сбора).
- Левая и правая колонки приходят одним запросом — это один запрос, не два.
- Счётчик: `wordstat_request_log`, показ «потрачено за запуск / за месяц». Лимитов пока нет; позже — по тарифу через админку.

## Сбор (фон)

Очередь `wordstat`, отдельная группа supervisor `cabinet-titlo-wordstat`, `numprocs=2` (добавить в `deploy-titlo.sh` и список групп для рестарта).

1. `StartWordstatRun` — создаёт `wordstat_run_seeds` из затравок, ставит по джобе на затравку.
2. `CollectWordstatSeed` — лимитер → запрос → фильтр минус-слов → `phrase_key` → upsert в группу затравки (существующие не трогаем, только обновляем `freq`) → при `depth` ставит дочерние затравки в пределах лимитов → обновляет прогресс run.
3. Ретраи: сетевая ошибка и «слишком много запросов» — `release()` с нарастающей паузой (10, 30, 90 с), до 5 попыток; неверный ключ / нет баланса — run `failed` с понятным текстом без имени поставщика.
4. Завершение: когда все seeds в финальном статусе — run `done`, итоги в карточке.
5. Отмена: кнопка «Остановить» — run `cancelled`, необработанные seeds пропускаются.

Прогресс в UI — опрос `GET run/{id}/status` раз в 3 с, пока run активен (без websockets на этапе 1).

## Интерфейс

- Список проектов: домен, регион, групп / фраз, последний сбор, кнопка «Новый проект».
- Проект: слева группы (счётчики фраз и суммарная частотность, переименование / слияние / удаление без перезагрузки), справа таблица фраз группы: фраза, частотность, источник, глубина; поиск по таблице, сортировка, массовые действия (перенести в группу, в минус, удалить).
- Блок «Собрать»: textarea, выбор пресета (Select2 при ≥10), «Сохранить как пресет», предпросмотр, «Запустить».
- Таблица — нативная `<table>` со скроллом и клиентским поиском (без DataTables), данные — JSON в `<script type="application/json">`.
- Числа с пробелом тысяч; регионы — Select2 с поиском; подсказки — `site-audit-tip` / общий `ui_tooltip`, без `title=`.
- Формы на `cabinet-ajax-form.js`.
- Файлы: `resources/views/wordstat-keywords/…`, `public/js/cabinet-wordstat-keywords.js`, `public/css/cabinet-wordstat-keywords.css` (scope `.cabinet-wsk-page`), переводы в `resources/lang/ru.json`.
- Пункт меню и право `Wordstat Keywords` — миграцией, как у SEO Checklist.

## Выгрузка (этап 1)

XLSX: Группа, Фраза, Частотность, Точная (пусто до этапа 2), Источник. Выгружаются `active` фразы проекта или выбранной группы.

## Этап 2 — чистка

- Список слов из фраз проекта с частотой употребления: клик → в минус-слова проекта, фразы с ним уходят в `minus` (обратимо).
- Неявные дубли: перестановки и словоформы по `phrase_key` с леммой; оставить фразу с большей частотностью.
- Фраза в двух группах: список конфликтов, выбор группы.
- Точная частотность пачкой для выбранных / всех `active`.
- Добор из поисковых подсказок (`SearchSuggestionsService`), источник `suggest`.
- Маркер коммерция / информационная (`PhraseCommerceService`).
- Передать в кластеризатор (группа или проект) и в проект мониторинга.

## Этап 3 — автоматический режим «по сайту»

- Источник страниц на выбор:
  - последний обход Site Audit этого домена (`site_audit_pages`: URL, TITLE, H1, noindex, статус);
  - быстрый сбор по `sitemap.xml`: на старте жёстко **до 30 страниц**, фильтр URL «включить / исключить» по маске, лимит поднимается вручную;
  - свой список URL (TITLE и H1 подтягиваем сами).
- Отбрасываем: не 200, noindex, неканонические, пагинацию, фильтры с параметрами, пустой H1 и TITLE.
- Страница → группа (`name` = H1, иначе TITLE; `page_url`).
- Затравки по правилам: H1 → TITLE без бренда (по домену и повтору в TITLE), города проекта, «купить», «недорого», «цена», «в Москве» и т.п.; дедуп; 1–3 затравки на страницу. Опционально «дочистить через AI» (`AiChatGateway`) — 3–5 затравок на страницу.
- Обязательный экран проверки затравок с оценкой запросов; без подтверждения сбор не стартует.
- Если сайт подключён к Яндекс Вебмастеру / GSC — к группе добавляются реальные запросы страницы (источник `webmaster` / `gsc`).
- Дальше — обычный сбор этапа 1 с пресетом.

## Ошибки и тексты

- Нет баланса / ключ неверный: «Сбор частотности временно недоступен, попробуйте позже» + запись для админа в лог.
- Пустая колонка — не ошибка: затравка `done`, 0 фраз.
- Слишком длинная фраза (> 400 символов) или > 7 слов — отклоняем на предпросмотре.

## Проверка

- Unit: разбор ввода (все 4 формата), `phrase_key`, фильтр минус-слов, оценка запросов.
- Feature: создание проекта, запуск run с фейковым HTTP-ответом Wordstat → фразы в группах, повторный запуск не дублирует, отмена.
- Smoke на local с реальным API на 1–2 затравках; на prod — после деплоя одна затравка.
