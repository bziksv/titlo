# Спецификация: статьи словаря titlo.ru, batch 7

## Что делать

Создать файлы `lib/content/glossary/terms/<slug>.ts` — по одному на термин.
Регистрацию в `index.ts` и `scripts/verify-glossary.mjs` НЕ трогать: это делает координатор.

## Образец

Прочитай целиком `lib/content/glossary/terms/chpu.ts` — это эталон формы, стиля и объёма.
Скопируй структуру, но НЕ копируй текст: содержание у каждого термина своё.

## Тип

```ts
import type { GlossaryTerm } from "../types";

/**
 * Бриф: кабинет #<id> «<Термин>».
 * Google MSK TOP-20, story <storyId>, запрос «<запрос>», 20.11.2026.
 * Рекомендации: балл <балл>, важные <важные>%, tf <tf>%, ширина 100, плотность <плотность>, символов <символов>.
 */
export const <CONST>: GlossaryTerm = { ... };
```

CONST — slug в UPPER_SNAKE: `khlebnye-kroshki` → `KHLEBNYE_KROSHKI`.

## Обязательные поля

`slug`, `term`, `aliases` (5-7 вариантов), `categoryId`, `h1`, `seoTitle` (без « | Титло»),
`seoDescription`, `short`, `definition`, `sections`, `modules`, `related` (6-12 названий),
`takeaways` (4-6), `faq` (5-6), `datePublished: "2026-11-20"`, `dateModified: "2026-11-20"`.

## Обязательные блоки (минимум по одному на статью)

- `p` — обычные абзацы
- `ul` со `style: "check"` или `"cards"` или `"mistakes"`
- `callout` с `variant: "tip" | "important" | "mistake"`
- `compare` — карточки сравнения `{ title, text }` (первый ряд — заголовки колонок)
- `flow` — схема `steps: [{ label, note }]`
- `steps` — пошаговая инструкция `items: [{ title, text }]`
- `table` — минимум 5 строк в `rows`, обязателен `caption`

Таблиц делай 3-6. Разделов (`sections`) — 10-14, у каждого `id` (латиница), `title`, `tocLabel` (1-2 слова).

## Жёсткие запреты

1. **Никаких чисел в заголовках** — ни в `h1`, ни в `title` разделов, ни в `tocLabel`, ни в заголовках подразделов.
   Не «5 способов», а «Способы». Не «Топ-10 ошибок», не «B2B».
   Исключение: код ответа внутри фразы («Что такое ошибка 500»), но заголовок не начинается с цифры.
   Заголовок не начинается с символа `✕ × → + − -`.
2. **Ни слова про методику**: нельзя упоминать анализатор, ТОП-20, «Рекомендации», ТЗ, LSI, Wordstat,
   «по данным исследования». Комментарий-бриф в шапке файла — можно, он не рендерится.
3. **Ссылки только** в формате RichText `[текст](/slovar/<slug>/)`, и только на ОПУБЛИКОВАННЫЕ термины.
   Список опубликованных — `briefs/published-index.json` (120 штук). Ссылка на неопубликованный slug
   ломает проверку. Не ссылайся на термины из batch 7, кроме тех, что уже написаны.
4. **Никаких выдуманных фактов**: ни процентов роста, ни «исследований», ни дат апдейтов.
   Числа допустимы только общеизвестные (коды ответа, лимиты стандартов) или как явный пример.
5. Никаких ссылок на «Словарь» и хаб в тексте статьи.
6. Без воды и вступлений «в современном мире». Короткие абзацы, 2-4 предложения.

## Объём и лексика — главное

Целевое число символов указано в брифе по каждому термину. Ориентир: **цель × 1.4–1.6**,
то есть статья должна быть заметно длиннее рекомендации. Меньше цели — не писать.

В брифе есть таблица «слова с целевым числом вхождений». Эти слова нужно органично
использовать в тексте — по смыслу, не списком. Покрытие важных слов должно быть
не ниже рекомендации, лучше с запасом. Для этого:
- используй синонимы и смежные понятия, а не повторяй одну фразу;
- пиши конкретно: примеры, случаи, что делать и чего не делать;
- не вставляй города, бренды конкурентов, мусор из баннеров и меню.
